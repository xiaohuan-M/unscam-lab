# 部署与更新

## 本机

Node 22+，复制 `.env.example` 为 `.env`，运行 `npm start`。没有运行时第三方依赖。建议先在本地通过所有故事和一次真实模型请求，再共享给他人。

## 静态部署

执行 `npm run build`，上传 `dist/` 的全部内容。应用使用相对路径，支持 `/unscam-lab/` 等路径。需要 HTTP(S)，不能直接通过 file:// 打开。静态站点不提供 `/api/*`，应用在配置探测失败后使用本地模式。

GitHub Pages 工作流只接受手动触发。在 Settings → Pages 选择 GitHub Actions 后运行工作流。不要将 .env 放进 public 或 dist，模型密钥不应存在静态文件中。

## 完整服务

默认监听 `127.0.0.1:3000`。Docker 默认绑定容器内 `0.0.0.0`，APP_MODE 为 public。

- 通过 TLS 反向代理提供访问；`PUBLIC_ORIGIN` 填最终精确源，如 `https://learn.example.com`，不加末尾 `/`。
- 公开 AI 服务要求至少 16 字符的 APP_TOKEN。请用密码管理器生成随机值，不使用示例口令。
- 健康检查：`GET /api/health`，只返回版本和状态。
- 不记录请求正文、Authorization、X-LLM-Key、X-App-Token；本应用不记录这些值，反向代理也应遵守。
- 不信任 X-Forwarded-For；每 IP 限流可能在代理后合并计数。没有代理信任链时，不应直接使用客户端提交的转发头。
- 日预算在内存内按 UTC 日计数；重启归零。需要硬成本上限时，同时在模型服务商设置额度。
- 三个并发名额、20 秒上游超时、12 KB 请求与 24 KB 模型响应限制，防止单次请求无限消耗。
- APP_TOKEN 是共享 AI 使用口令，不是用户系统。该版本不具备多租户隔离和用户级计费。

## 配置模型

服务器固定基础 URL，用户不能通过聊天或接口参数指定目标地址。只允许 HTTPS，或精确 localhost/127.0.0.1/[::1] 的本机 HTTP。禁止 URL 嵌入用户名密码、查询字符串或 fragment；禁止跟随重定向。

设置页可测试连接。超时、认证失败、JSON 不合规都不会阻断本地故事。每个服务商的模型兼容性由部署者实际验收；测试不使用任何真实用户凭据。

## 升级与回退

1. 备份当前代码版本与 .env；学习记录由每位用户在界面导出。
2. 拉取新代码，运行 `npm run verify`；容器或静态产物从已验证版本构建。
3. 替换完整产物，避免混合不同版本的 app.js 与数据。
4. 浏览器提示新版后，用户可保存进度并更新。建议在下一次练习前完成更新。
5. 回退时部署完整旧产物。不要手动删用户 localStorage；新版备份保留以便再升级。

如果无法使用浏览器存储，应用继续以临时进度运行并提示导出。不是跨设备云同步。
